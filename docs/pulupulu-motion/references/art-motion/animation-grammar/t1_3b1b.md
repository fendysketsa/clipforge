# t1_3b1b · 3Blue1Brown-style maths / concept visualisation

> One-line grammar: **On a black background put only "the one thing currently being explained", use smooth transformation (Transform) to turn the previous concept directly into the next, colour = the concept's name, and almost never cut.**
>
> Demo film: `scripts/art-motion/engine/demos/t1_3b1b/` (render with `render.py --film demos/t1_3b1b`) (8s, 3 shots) · overview `assets/animation-grammar/t1_3b1b_overview.jpg` · code `scripts/art-motion/engine/demos/t1_3b1b/`

## Pre-flight checks

1. **For every shot, write down "who becomes whom".** What is the previous object and what is the next one (grid → circle, one curve → another, pixels → neurons). If you cannot write that transformation sentence, don't use t1 — switch to y5 or y3.
2. **Frame one is the object.** Axes, grid and curve come out first; title and formula arrive later; do not Write a title line at second 0.
3. **Count the words on screen.** At most 2 key points on screen at any moment; before the third appears, the earlier ones must either turn into a graphic or be taken away. Key points Written one by one as a list is just a black-background PowerPoint.
4. **Write the colour table first.** One colour per concept; symbols in the formula share the colour of the object on screen; no more than 4 semantic colours in the whole film.
5. **Be still during wait.** No uniform slow push, breathing or floating; the camera moves only when you need to look at the next object, and stops as soon as it has moved (see ③ "Camera").

## ① When to use it

- **Use**: to explain how one mechanism "turns step by step into another thing" — neural-network forward pass, attention, matrix transformations, gradient descent, probability distributions, algorithm flow. It fits best when the voiceover is made of **action-type sentences** like "we flatten this image into a column" or "each pixel is multiplied by a weight": each sentence corresponds to one Transform.
- **Use**: when the audience needs to "see the maths" — symbols in the formula map one-to-one onto objects on screen (the W in the formula is blue, and so are the connections).
- **Don't use**: product launches, mood/brand films (black background white lines are too cold and too slow); real data trends (that is t3's job); when the voiceover is opinion, story or a punchline (there is no object that can "transform", forcing it leaves only decoration). Fast cutting under 8 seconds doesn't work either — 3b1b's native rhythm is 1–3 seconds per animation + 1 second hold (see ⑤), and squeezing it into 8 seconds with 3 shots is already the ceiling.

## ③ Motion paths

- **Easing**: default `smooth = 6t⁵−15t⁴+10t³` (the 3b1b version, velocity and acceleration both zero at both ends; the CE version is sigmoid, `MO.smoothCE`). **Almost every animation uses it**; linear is only for Write, uniform rotation, and the advance of ShowPassingFlash. `there_and_back` is for Indicate, `rush_into/rush_from` for "rush in / rush out".
- **Default duration**: Animation run_time=1s, wait=1s. 2023–24 source statistics: explicit run_time most commonly 2s (481 times) > 3s (333) > 1s (187) > 4s (145).
- **LaggedStart**: default lag_ratio 0.05; 0.1 is the most common in the source. Implementation: `MO.lagged(i, n, p, r)` (the i-th occupies `[i·r, i·r+1]`, total length `1+(n−1)r`). This film uses 0.01 for the 100 pixels→neurons (done in 1.1s) and 0.006 for the 160 connections.
- **Write**: linear; <15 sub-objects 1s, otherwise 2s; lag between sub-objects = `min(4/(n+1), 0.2)`; each character "outline first, fill after" (`DG.math`/`DG.write`: lineDash advances the stroke → the last 60% fills in while the stroke fades out).
- **Transform**: resample both shapes to the same point count, **aligned starts** (both start from the upper-left and go clockwise), straight-line interpolation point by point (path_arc=0) + colour interpolation. `DG.rectPts/circlePts/morph`. This film: grid→circle (pixels→neurons), weight grid→flies to one neuron (weighted sum).
- **Entrances/exits**: FadeIn/FadeOut with shift (this film 24–40px, "bottom to top" or "fade upward out"); new-layer neurons fade in from 24px on the right; whatever is being replaced shrinks to a point and merges into the "⋮".
- **Signal**: ShowPassingFlash (time_width 2) — duplicate the connection, dye it yellow, width ×1.5, visible segment `[max(0,u−2), min(1,u)]`, u from 0 to 3 (`DG.flash`), staggered per input row with lag 0.04.
- **Camera**: MovingCameraScene frame animation; camera moves are events: hold → push to the next object to look at → hold. Pushing by default uses 3b1b's native smooth single push (about 1s, `CAM.track`'s push／to); use a fast push only where the conclusion lands (0.28s pushing in 18–32%, an accent, once or twice per section); 3D scene orbit 0.5–3°/s (3b1b default 1°/s) only when explaining spatial relations. In this film shot 2 pushing toward the output layer (1→1.08) is an event push; shot 1's uniform slow push 1→1.025 around the grid is the old "slow push on every shot" practice, new films should not copy it.
- **Stillness in wait**: the original is usually **still** during wait — this is the biggest difference between 3b1b and launch films. Do not add uniform slow push, breathing or floating to manufacture motion; the sense of movement comes from the next Transform.

## ④ Transitions (4 common ones)

1. **Transform continuation (no cut)**: last frame of the previous shot = first frame of the next, using morphing to turn the old object into the new one. In this film shot 1→2: 100 pixel squares become a column of input neurons, and shot 2's first frame is pixel-for-pixel identical to shot 1's last frame. This is 3b1b's number-one transition and accounts for the vast majority.
2. **Camera zoom-through**: the camera pushes exponentially into an object (`zoom = Z^e`, constant perceived speed), the object's circumference becomes an opening, and inside is the new image. `TRANSITIONS.zoomThrough`, parameters `live:true` (the old shot keeps pushing the camera itself while lt>duration, vectors are redrawn so it stays sharp), `r0` (object radius), `zoom ≥ 1100/r0` (otherwise the opening does not fill the screen and the last frame jumps), `focus` (the new image's subject waits in the centre of the opening first, and only returns to position when e>0.55). In this film shot 2→3: first outline the hidden neuron with activation 0.95 in yellow ("let's look at this one"), then push in on it 48×, 0.75s.
3. **FadeOut(shift=UP) + FadeIn(shift=UP)**: when changing topic everything fades upward out, new content fades in from below (`TRANSITIONS.fadeShift`).
4. **ReplacementTransform for titles/formulas**: the old formula's symbols move to the position of the same-named symbol in the new formula (TransformMatchingTex, 3b1b version default 2s); symbols that don't match fade out and in.

## ⑤ Pacing and text

- **Shot duration**: the original is a continuous scene, a single animation 1–3s followed by wait 1s; one "shot" (one concept) is often 8–20s. This film's 8 seconds and 3 shots (2.6/2.8/2.6s) is a **compressed version**; for real voiceover use it should be stretched 2–3×.
- **Syncing with the voiceover**: Grant's process is **lay out the animations first, record the voiceover after** ("I start by laying out all of the animations… then once I record the voiceover, the actual editing is like a day"). So the sync rule is "one sentence = one animation": the animation starts when the sentence speaks the action verb, and once the sentence settles there is a wait of about 1s so the audience can look.
- **Text**: titles/questions are Written before the action (ask first, then perform); formulas appear together with the image, in the same colour; numbers (0.95) follow the fill count and never appear before the image. In Chinese, at most one line of title + one line of note per screen.
- **FAQ principle**: "Every movement on the screen should be deliberate, with an identifiable purpose" — delete any motion that has no explanatory purpose.

## ⑧ The 3 easiest things to get wrong

1. **Treating "glow" as 3b1b's signature, adding bloom and a deep-blue gradient background.** The original is pure black + high-saturation thin lines + ×1.5 saturation, with almost no halo. Add a halo and it becomes a "techy PowerPoint".
2. **Using linear or ordinary ease throughout, with animations that are fast and numerous.** The default must be smooth (fifth-order polynomial), one animation 1–3s then stop 1s; every motion must correspond to a verb in the voiceover.
3. **Changing the colour coding midway / too many colours.** One colour = one concept, symbols in the formula share the colour of the object on screen; past 3–4 semantic colours the audience stops remembering.
